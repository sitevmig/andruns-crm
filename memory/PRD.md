# PRD — CRM для холодных продаж (создание сайтов российскому бизнесу)

## Оригинальная задача
Внутренняя CRM для 3 администраторов: загрузка базы организаций из Excel/CSV, дедупликация,
статусы, очередь рассылки, email + Telegram (MTProto), история сообщений, экспорт в Excel,
резервные копии, глобальная остановка рассылки. Интерфейс на русском, строгий десктопный стиль.

## Выборы пользователя
- Auth: JWT (email+пароль)
- Email: mock-абстракция провайдера (реальные ключи позже)
- Telegram: полная структура в MOCK/демо-режиме (готово к внешнему MTProto-воркеру)
- БД: MongoDB
- Дизайн: строгий деловой светлый стиль, плотные таблицы

## Архитектура
- Frontend: React (craco) + Tailwind + shadcn/ui, alias `@/`
- Backend: FastAPI, роутеры в `backend/routers/*`, фоновый asyncio-worker очереди (15с)
- MongoDB (motor). Секреты только в env. `.env.example`, `.gitignore`, `README.md` подготовлены.

## Персоны
- Администратор (полный доступ, ролей нет)

## Реализовано (2026-07-11)
- JWT-авторизация, 3 сид-админа, журнал входов, brute-force, сессии, смена пароля, управление админами
- Организации: таблица, поиск/фильтры/сортировка, сохранённые фильтры, массовые операции, карточка (сведения/сообщения/изменения/действия), DNC
- Импорт Excel/CSV: мастер (загрузка→маппинг→анализ→подтверждение→отчёт), дедуп по 6 признакам, нормализация телефона, сохранение статуса/DNC/истории при повторном импорте
- Шаблоны (email/telegram) с переменными и предпросмотром
- Очередь + фоновый worker (MOCK-отправка), stop-all/resume/stop-email/stop-telegram/clear/retry
- Ответы (входящие, mock-регистрация), Дубли (ручное объединение), Экспорт (xlsx с актуальными статусами), Резервные копии
- Дашборд (карточки + воронка), Настройки (общие/рассылки/telegram/email/админы/безопасность)
- Тестирование: backend 45/45, frontend core-flows 100%

## Итерация «Реальные каналы» (2026-07-12)
- Email: реальная отправка через Resend HTTPS API (абстракция email_provider.py, без SMTP/IMAP — Render блокирует порты). Авто-проверка входящей почты не реализована (ответы менеджер видит в своей почте, статус меняет вручную).
- Telegram: реальный MTProto через Telethon без постоянного worker. Вход по номеру+код (+2FA), тест соединения, отправка одному получателю, «Проверить ответы», зашифрованная per-user сессия. При ошибке подключения показывается реальная техническая ошибка (без имитации).
- Шифрование сессий: PBKDF2(SHA256, 390k)→Fernet из ENCRYPTION_KEY+FERNET_SALT (обязательны, fail-fast, стабильные параметры).
- Симуляция отправки убрана: фоновый queue-worker отключён, /api/queue/process возвращает 400.
- Новые файлы: crypto.py, email_provider.py; переписан routers/integrations.py; правки Settings.jsx (TelegramSettings), server.py, queue.py.
- НЕ реализовано в этой итерации (в ит.2): роли/менеджеры, «Взять в работу», атомарное закрепление, «Мои/Свободные клиенты», переименования интерфейса, массовая рассылка через очередь.

## Прежний MOCK / демо-режим (заменён реальными каналами)
- Email отправка (`/api/email/*`), Telegram MTProto (`/api/telegram/*`), обработка очереди (`worker.py`) — симуляция
