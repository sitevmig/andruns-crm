# CRM для холодных продаж (создание сайтов российскому бизнесу)

Внутренняя CRM-система для трёх администраторов: загрузка базы организаций из Excel/CSV,
дедупликация, статусы, очередь рассылки, email и Telegram (MTProto), история сообщений,
экспорт в Excel и резервное копирование.

## Технологии
- **Frontend**: React (CRA + craco), Tailwind, shadcn/ui
- **Backend/API**: FastAPI (Python), фоновая очередь на asyncio
- **База данных**: MongoDB
- **Модули**: импорт Excel/CSV (pandas + openpyxl/xlrd), email (абстракция провайдера), Telegram (MTProto worker)

> Email и Telegram в текущей версии работают в **демо-режиме** (отправка симулируется).
> Логика, БД и интерфейс полностью готовы к подключению реального SMTP/провайдера и постоянного MTProto-воркера.

## Локальный запуск
### Backend
```bash
cd backend
pip install -r requirements.txt
# заполнить .env (см. .env.example)
uvicorn server:app --host 0.0.0.0 --port 8001 --reload
```
### Frontend
```bash
cd frontend
yarn install
# указать REACT_APP_BACKEND_URL в frontend/.env
yarn start
```

## Environment variables
См. `.env.example`. Основные:
- `MONGO_URL`, `DB_NAME` — подключение MongoDB
- `JWT_SECRET` — секрет для JWT
- `ADMIN_EMAILS` — список администраторов
- `EMAIL_PROVIDER_API_KEY`, `EMAIL_FROM_ADDRESS` — email-провайдер
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION_SECRET` — Telegram MTProto
- `ENCRYPTION_KEY` — шифрование Telegram-сессии

Секреты хранятся **только** в environment variables и не попадают в репозиторий (см. `.gitignore`).

## Подключение базы данных
Укажите `MONGO_URL` и `DB_NAME`. При старте создаются индексы, сидируются 3 администратора и демоданные.

## Подключение email
Модуль email построен как абстракция провайдера (`routers/integrations.py`). Для продакшена
замените mock-реализацию на SMTP/SendGrid/Resend, используя `EMAIL_PROVIDER_API_KEY`.
Поддерживается позднее подключение входящей почты через webhook.

## Подключение Telegram
Используется официальный Telegram API/MTProto через отдельный **постоянно работающий** worker-сервис
(не serverless). Сессия хранится в зашифрованном виде и не попадает в GitHub.
В настройках: подключение/отключение аккаунта, проверка соединения, тестовое сообщение, журнал ошибок.

## Развертывание
Проект готов к размещению в приватном GitHub-репозитории и развёртыванию через Vercel/другой хостинг.
Фоновая очередь и Telegram-воркер выносятся в отдельный постоянный backend-сервис
(serverless не подходит для постоянной MTProto-сессии).

## Импорт Excel
Раздел «Импорт»: выбор файла → предпросмотр → сопоставление столбцов → проверка (новые/обновляемые/
дубли/ошибки) → подтверждение → отчёт (скачивается в Excel). Импорт не удаляет записи,
обновляет контакты, сохраняет статусы, историю и флаг «Не связываться».

## Резервное копирование
Раздел «Экспорт»: ручное создание копии, дата последней копии, скачивание, восстановление
(с подтверждением). Копии не сохраняются в GitHub.

- `manager3@crm.ru` / `Admin123!`

## Ограничения текущей версии
- Email и Telegram работают в демо-режиме (симуляция отправки).
- Входящая почта через webhook не реализована (предусмотрена архитектурно).
- Нет ролей: все три администратора имеют полный доступ.
- Автоматический анализ отказов ИИ отсутствует — статусы «Отказ»/«Не связываться» ставятся вручную.
